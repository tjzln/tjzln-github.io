## 1. 연구 배경

최근 대규모 언어 모델(LLM, Large Language Model)의 코드 이해 및 추론 능력이 향상되면서, 소프트웨어 보안 분야에서도 LLM을 활용한 보안약점 탐지 연구가 활발하게 이루어지고 있다.

기존 정적 분석 도구는 사전에 정의된 규칙이나 패턴을 기반으로 보안약점을 탐지하는 반면, LLM은 코드의 문맥과 의미를 분석해 보안약점이 발생할 가능성을 판단할 수 있다.

하지만 LLM을 활용한 보안약점 탐지에서는 **어떤 형태의 코드를 모델에 입력하느냐** 역시 중요한 문제이다.

동일한 프로그램이라도 코드의 표현계층에 따라 포함된 정보와 구조가 달라지기 때문이다.

대표적인 코드 표현계층은 다음과 같다.

| 표현계층 | 특징 |
|---|---|
| 고급언어(High-Level Language) | 변수명, 자료형, 함수 구조 등 개발자가 작성한 코드의 의미 정보를 포함 |
| 중간언어(Intermediate Representation) | 컴파일러가 사용하는 중간 표현으로, 연산 및 제어 흐름을 명시적으로 표현 |
| 어셈블리어(Assembly) | 프로세서 명령어와 레지스터 중심으로 프로그램의 저수준 동작을 표현 |

고급언어는 프로그램의 의미를 비교적 직관적으로 파악할 수 있다는 장점이 있다. 반면 중간언어와 어셈블리어는 실제 연산 및 실행 구조에 가까운 정보를 제공한다.

이처럼 표현계층마다 제공하는 정보가 다르므로, LLM의 보안약점 탐지 성능에도 차이가 발생할 수 있다.

## 2. 연구 목적

본 연구에서는 **동일한 프로그램을 서로 다른 코드 표현계층으로 변환했을 때, LLM의 보안약점 탐지 성능이 어떻게 달라지는지** 분석하고자 했다.

이를 위해 다음 세 가지 표현계층을 비교 대상으로 선정했다.

1. C/C++ 소스코드
2. LLVM Intermediate Representation(LLVM IR)
3. x86-64 Assembly

세 표현계층에 동일한 LLM 기반 보안약점 탐지 방식을 적용하고, 각 계층에서 나타나는 탐지 성능의 차이를 비교했다.

이를 통해 특정 표현계층이 보안약점 탐지에 유리한지 확인하고, LLM 기반 소프트웨어 보안 분석에서 입력 코드 표현 방식의 중요성을 검토하는 것이 연구의 목적이다.

## 3. 실험 설계 및 방법

### 3.1. 실험 데이터셋

실험에는 **Juliet Test Suite의 C/C++ 데이터셋**을 사용했다.

Juliet Test Suite는 다양한 CWE(Common Weakness Enumeration) 유형에 대한 보안약점 사례를 포함하는 테스트 데이터셋이다.

CWE는 소프트웨어에서 발생할 수 있는 보안약점을 유형별로 분류한 체계이며, Juliet은 이러한 보안약점이 포함된 코드와 비교 대상을 제공하므로 보안약점 탐지 성능 평가에 활용할 수 있다.

### 3.2. 코드 표현계층 변환

동일한 프로그램에 대해 서로 다른 표현계층의 입력 데이터를 구성했다.

**① 고급언어: C/C++**

원본 C/C++ 소스코드를 사용했다.

변수명, 자료형, 조건문, 반복문, 함수 호출 등 원래 코드의 구조와 의미 정보를 확인할 수 있다.

**② 중간언어: LLVM IR**

LLVM 컴파일러 인프라를 활용하여 C/C++ 소스코드를 LLVM IR로 변환했다.

LLVM IR은 소스코드보다 저수준의 표현이지만, 연산과 제어 흐름을 구조적으로 나타낼 수 있다.

**③ 어셈블리어: x86-64 Assembly**

C/C++ 코드를 x86-64 명령어 형태로 변환했다.

레지스터 연산, 메모리 접근, 분기 명령어 등을 통해 프로그램이 수행하는 저수준 동작을 확인할 수 있다.

이처럼 코드 표현 방식만 달라지는 비교 환경을 구성하여, 표현계층에 따른 탐지 성능 차이를 분석했다.

### 3.3. LLM 기반 보안약점 탐지

보안약점 탐지 모델로 **Claude Sonnet 4.6**을 사용했다.

각 표현계층의 코드를 LLM에 입력하고 보안약점 존재 여부에 대한 판단 결과를 수집했다.

이후 모델의 예측 결과와 데이터셋의 정답을 비교하여 탐지 성능을 평가했다.

**[그림 1. 코드 표현계층별 LLM 기반 보안약점 탐지 실험 구성도 삽입]**

### 3.4. 성능 평가 지표

표현계층별 탐지 성능을 비교하기 위해 다음 네 가지 지표를 사용했다.

| 평가 지표 | 의미 |
|---|---|
| Accuracy | 전체 예측 중 올바르게 판단한 비율 |
| Precision | 보안약점이 있다고 예측한 사례 중 실제 보안약점이 있는 비율 |
| Recall | 실제 보안약점이 존재하는 사례 중 올바르게 탐지한 비율 |
| F1-score | Precision과 Recall의 조화평균 |

Accuracy는 전반적인 분류 성능을 확인하는 데 사용한다.

Precision은 잘못된 보안약점 경고를 얼마나 줄였는지와 관련되며, Recall은 실제 보안약점을 얼마나 놓치지 않고 탐지했는지를 나타낸다.

따라서 단일 지표만 비교하기보다는 여러 지표를 종합하여 각 표현계층의 탐지 특성을 분석하고자 했다.

## 4. 실험 결과 및 분석

실험 결과, 세 표현계층에서 서로 다른 보안약점 탐지 성능이 나타났다.

**[표 1. 표현계층별 Accuracy, Precision, Recall, F1-score 실험 결과 삽입]**

### 4.1. 고급언어(C/C++)

고급언어는 **Accuracy, Recall, F1-score에서 세 표현계층 중 가장 높은 성능**을 보였다.

C/C++ 소스코드는 변수명, 자료형, 함수 호출 및 제어 구조 등의 정보를 포함하므로 모델이 코드의 의미와 동작을 파악하는 데 유리할 수 있다.

특히 Recall이 높게 나타났다는 점은 실제 보안약점이 존재하는 사례를 상대적으로 많이 탐지했다는 것을 의미한다.

이를 통해 원본 소스코드에 포함된 고수준 의미 정보가 LLM 기반 보안약점 탐지에 중요한 역할을 할 가능성을 확인했다.

### 4.2. 중간언어(LLVM IR)

LLVM IR은 **Precision에서 가장 높은 성능**을 보였으나, Accuracy, Recall, F1-score에서는 가장 낮은 성능을 기록했다.

이는 LLVM IR을 입력받은 모델이 보안약점이 있다고 판단한 사례 중 실제 보안약점이 존재하는 비율은 상대적으로 높았지만, 실제 보안약점 중 놓친 사례도 많았음을 의미한다.

LLVM IR은 명시적인 연산과 제어 흐름을 제공하지만, 소스코드의 일부 고수준 의미 정보가 변환 과정에서 달라지거나 사라질 수 있다.

이러한 표현 특성이 탐지 성능에 영향을 주었을 가능성이 있다. 다만 성능 차이의 정확한 원인을 규명하기 위해서는 추가적인 분석이 필요하다.

### 4.3. 어셈블리어(x86-64)

어셈블리어는 **모든 평가지표에서 고급언어와 중간언어 사이의 성능**을 보였다.

어셈블리어는 소스코드에 존재하는 변수명이나 고수준 제어 구조를 직접적으로 제공하지 않지만, 메모리 접근, 레지스터 연산 및 분기 명령어 등을 통해 프로그램의 동작을 표현한다.

실험 결과는 LLM이 이러한 저수준 정보를 활용하여 보안약점을 일정 수준 탐지할 수 있음을 보여준다.

또한 어셈블리어가 LLVM IR보다 높은 종합 탐지 성능을 기록했다는 점도 주목할 만하다.

이 결과는 코드 표현계층이 낮아질수록 LLM의 탐지 성능이 일관되게 감소하는 것은 아니라는 점을 시사한다.

### 4.4. 결과 종합

실험 결과를 정리하면 다음과 같다.

| 평가 지표 | 가장 높은 성능 |
|---|---|
| Accuracy | C/C++ |
| Precision | LLVM IR |
| Recall | C/C++ |
| F1-score | C/C++ |

전체적으로 C/C++ 소스코드가 높은 탐지 성능을 보였으나, Precision에서는 LLVM IR이 우세했다.

어셈블리어는 모든 지표에서 중간 수준의 성능을 기록했다.

이러한 결과를 통해 **LLM 기반 보안약점 탐지에서는 코드의 표현계층에 따라 탐지 성능뿐 아니라 오탐과 미탐의 특성도 달라질 수 있음**을 확인했다.

## 5. 연구의 의의와 한계

### 5.1. 연구의 의의

본 연구에서는 동일한 프로그램의 코드 표현 방식을 달리하여 LLM 기반 보안약점 탐지 성능을 비교했다.

이를 통해 다음과 같은 결과를 확인했다.

- 고급언어가 전반적으로 가장 높은 탐지 성능을 보였다.
- 중간언어는 높은 Precision을 보였으나 Recall은 상대적으로 낮았다.
- 어셈블리어에서도 LLM 기반 보안약점 탐지가 가능했으며, 모든 성능지표에서 중간 수준의 결과가 나타났다.

이러한 결과는 LLM을 활용한 보안약점 탐지에서 모델의 성능뿐 아니라 **모델에 제공하는 코드의 표현 방식 역시 고려해야 한다는 점**을 보여준다.

특히 원본 소스코드를 확보하기 어려운 바이너리 분석 환경에서 중간언어나 어셈블리어를 활용할 때, 각 표현계층의 특성을 이해하는 데 참고할 수 있다.

### 5.2. 연구의 한계

본 연구는 특정 데이터셋과 단일 LLM을 기반으로 진행되었으므로, 실험 결과를 모든 LLM이나 소프트웨어에 일반화하기는 어렵다.

또한 코드 표현계층별 성능 차이를 확인했지만, 그 차이가 발생한 원인을 완전히 규명하지는 못했다.

향후에는 다양한 LLM을 대상으로 결과를 비교하고, CWE 유형별 탐지 성능을 분석할 필요가 있다.

또한 표현계층별 코드 길이와 정보 손실, 컴파일 최적화 수준 등에 따른 영향을 분석한다면 각 표현계층의 탐지 특성을 보다 구체적으로 설명할 수 있을 것이다.

## 6. 결론

본 연구에서는 C/C++, LLVM IR, x86-64 Assembly를 대상으로 코드 표현계층에 따른 LLM 기반 보안약점 탐지 성능을 비교했다.

실험 결과, 고급언어는 Accuracy, Recall, F1-score에서 가장 높은 성능을 보였으며, 중간언어는 Precision에서 가장 높은 성능을 기록했다. 어셈블리어는 모든 지표에서 중간 수준의 성능을 나타냈다.

이를 통해 코드의 표현계층이 LLM 기반 보안약점 탐지 성능에 영향을 미칠 수 있음을 확인했다.

본 연구는 특정 표현계층의 우수성을 단정하기보다는, **코드의 표현 방식에 따라 LLM이 보안약점을 탐지하는 특성이 달라질 수 있음을 실험적으로 비교했다는 점**에 의미가 있다.

향후에는 각 표현계층의 성능 차이가 발생하는 원인을 분석하고, 서로 다른 표현계층의 정보를 보완적으로 활용하는 방법까지 연구를 확장할 수 있을 것이다.
